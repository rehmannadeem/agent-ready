# API sources and verification boundaries

Inspected 10 November 2026; request API pinned to **2026-07**. The connected schema tool can track a newer API, so its results alone are insufficient. `checkSchema` obtains the full schema from the actual named store's pinned endpoint and validates all operations before mutation authorization. The client then validates every variables object. If introspection, parsing, field/type validation or variable coercion fails, execution stops.

- [productSet](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/productSet): synchronous product/variant creation; omitted list elements can be deleted on reconciliation. The script creates only after collision checks and never bulk-reconciles an unowned product.
- [ProductVariantSetInput](https://shopify.dev/docs/api/admin-graphql/2026-07/input-objects/ProductVariantSetInput): optionValues, sku, inventoryItem, inventoryQuantities and price fields. Initial inventory can be set at the selected existing locations on new variants.
- [collectionCreate](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/collectionCreate), [collectionAddProducts](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/collectionAddProducts): pinned API still documents the deprecated `input`/add paths used here. The exact pinned schema is the final validation gate. Membership is read first; additions are missing IDs only in arrays of at most 250.
- [Publication](https://shopify.dev/docs/api/admin-graphql/2026-07/objects/Publication), [publishablePublish](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/publishablePublish), [publishableUnpublish](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/publishableUnpublish): publications are explicit IDs. Product `publishedOnPublication` is checked separately for each returned publication. A channel label is not proof of UCP exposure.
- [DiscountCodeBasicInput](https://shopify.dev/docs/api/admin-graphql/2026-07/input-objects/DiscountCodeBasicInput), [discountCodeBasicCreate](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/discountCodeBasicCreate), [discountCodeBasicUpdate](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/discountCodeBasicUpdate): all-buyer context; collection-restricted percentage/fixed discounts; minimum subtotal and date window. No real customer ID is needed.
- [inventorySetQuantities](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/inventorySetQuantities): 2026-04+ `changeFromQuantity` CAS and `@idempotent` requirement are enforced for stock simulations/restores. No blind inventory adjustment retries.
- [productVariantsBulkUpdate](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/productVariantsBulkUpdate): controlled owned-variant price change. There is no atomic version predicate in this input; the limitation is recorded in the simulation journal.
- [API limits](https://shopify.dev/docs/api/usage/limits), [GraphQL rate limits](https://shopify.dev/docs/apps/build/apis/graphql-admin/rate-limits), [access scopes](https://shopify.dev/docs/api/usage/access-scopes): array bounds, cost-throttle handling, and write scopes providing corresponding read access. The stricter 50,000-variant resource threshold is used as the preflight stop boundary because pinned/current documentation conflict; this seed plus the observed 27-variant baseline stays below either threshold.

Schema validation proves API shape, not store permissions or commerce behavior. Final live evidence must include actual preflight, mutation outcomes, read-back verification, and the separate UCP/cart acceptance results. No result is manufactured if a credential, scope, publication, API capability or live test is unavailable.
